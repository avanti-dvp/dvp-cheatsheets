▶️ GitHub Actions Cheat Sheet

Guia rápido de workflows, triggers, contexts e syntax YAML para CI/CD

📁 Estrutura Básica de um Workflow

Os arquivos YAML devem estar localizados no diretório .github/workflows/ do seu repositório.

name: Meu Primeiro Workflow # Nome do workflow

on: [push] # Evento que aciona (Trigger)

jobs: # Agrupamento de tarefas
  build: # Identificador do job
    runs-on: ubuntu-latest # Máquina virtual (Runner)
    
    steps: # Sequência de tarefas (passos)
      - name: Fazer Checkout do Código
        uses: actions/checkout@v4
        
      - name: Instalar Dependências
        run: npm install
        
      - name: Executar Testes
        run: npm test

⚡ Principais Triggers (Eventos)

Eventos que iniciam a execução do seu workflow definidos em on:.

Sintaxe Descrição
on: push Aciona sempre que houver um push (qualquer branch/tag).
on: pull_request Aciona em criação, atualização ou merge de PRs.
on: schedule Aciona por agendamento (Expressão CRON).
Ex: - cron: '0 0 * * *' (Diariamente)
on: workflow_dispatch Permite execução manual do workflow via botão na interface do GitHub.

🎯 Filtros de Triggers (Branches, Paths e Tags)

Restrinja a execução do workflow a branches ou arquivos específicos.

on:
  push:
    branches:
      - main
      - 'releases/**'
    branches-ignore: # Não executa nestas
      - 'experiment'
    tags:
      - 'v1.*'
    paths:
      - 'src/**/*.js' # Executa só se arquivos js mudarem
    paths-ignore:
      - 'docs/**' # Ignora mudanças na pasta docs

🌐 Contexts (Variáveis do GitHub)

Informações sobre a execução, acessadas pela sintaxe ${{ <contexto> }}.

${{ github.actor }} Usuário que iniciou o workflow.
${{ github.repository }} Nome do repositório (ex: user/repo).
${{ github.ref_name }} Nome da branch ou tag (ex: main, v1.0).
${{ github.event_name }} O nome do evento que acionou (ex: push).
${{ job.status }} Status atual do job (success, failure, cancelled).

🔐 Secrets e Variáveis de Ambiente

Como usar dados sensíveis e gerenciar variáveis globais e de passo.

env: # Variáveis globais do workflow
  NOME_APP: "MeuAplicativo"

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Usar variáveis
        run: echo "Iniciando $NOME_APP"
        
      - name: Autenticar API
        run: ./script.sh --token $API_TOKEN
        env: # Variável local do step com Secret
          API_TOKEN: ${{ secrets.SUPER_SECRET_TOKEN }}

Dica: Secrets são configurados em Settings > Secrets and variables > Actions do repositório.

🔀 Estratégia de Matriz (Matrix)

Executa o mesmo job várias vezes simultaneamente com diferentes variáveis (ex: testar múltiplas versões de Node ou OS).

jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        node-version: [16.x, 18.x, 20.x]
        # Cria 3 jobs paralelos (um para cada versão)
    
    steps:
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}

📦 Actions Mais Usadas

As Actions prontas oficiais do GitHub que você vai usar em quase todo projeto.

actions/checkout@v4 Clona o seu repositório no runner para permitir a leitura do código.
actions/setup-node@v4 Instala e configura ambiente Node.js. (Existe similar para setup-python, setup-java, etc).
actions/upload-artifact@v4 Faz upload de arquivos gerados no workflow (ex: build, logs) para download no GitHub.
actions/download-artifact@v4 Baixa arquivos salvos pelo `upload-artifact` em jobs anteriores.
actions/cache@v4 Guarda cache de dependências (como node_modules) para acelerar builds futuros.

🔀 Condicionais (if) e Dependências (needs)

Controle o fluxo de execução entre jobs e passos.

jobs:
  build_test:
    runs-on: ubuntu-latest
    steps:
      - run: make build
      
      - name: Executa apenas se a branch for main
        if: github.ref == 'refs/heads/main'
        run: echo "Fazendo algo especial na main"

  # Esse job só inicia APÓS o build_test finalizar com sucesso
  deploy:
    needs: build_test
    runs-on: ubuntu-latest
    
    # Roda sempre, mesmo se os jobs anteriores falharem
    if: always() 
    steps:
      - run: ./deploy.sh
