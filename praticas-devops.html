♾️ Práticas DevOps Cheat Sheet

Guia de referência para Cultura, CI/CD, IaC, Observabilidade e DevSecOps

🧠 Cultura CALMS

DevOps não é uma ferramenta, é uma cultura. O framework CALMS define seus pilares principais.

Culture (Cultura): Quebrar silos entre Dev (Desenvolvimento) e Ops (Operações). Responsabilidade compartilhada.
Automation (Automação): Eliminar trabalho manual repetitivo (toil) para reduzir erros e acelerar entregas.
Lean (Enxuto): Produzir em lotes pequenos, minimizar desperdícios e focar em entregar valor contínuo.
Measurement (Medição): Tudo deve ser medido (Métricas, KPIs). Decisões baseadas em dados, não em intuição.
Sharing (Compartilhamento): Compartilhar conhecimento, código e responsabilidades. Blameless Post-mortems (Análises sem culpa).

🔄 CI vs. CD (Integração e Entrega)

Compreendendo o Pipeline Contínuo.

  • Continuous Integration (CI): Desenvolvedores fazem o merge do código na branch principal frequentemente (várias vezes ao dia). Aciona builds automáticos e testes de unidade. Previne o "Integration Hell".
  • Continuous Delivery (Entrega Contínua - CD): O código aprovado na CI é empacotado e fica pronto para ir para produção. A ida para produção exige uma aprovação ou o clique de um botão manual.
  • Continuous Deployment (Implantação Contínua - CD): É o próximo passo da Entrega. Se o código passar por todos os testes e etapas, ele vai automaticamente para produção. Sem intervenção humana.
Regra de Ouro: CI garante que o código está bom; CD garante que o deploy é repetível, seguro e fácil.

🏗️ Infraestrutura como Código (IaC)

Gerenciamento de recursos computacionais via arquivos de definição legíveis por máquina, ao invés de configurações interativas manuais (cliques).

Prática Descrição
Declarativo Você diz o que quer (ex: "Quero 3 servidores"), não como fazer (Terraform, Kubernetes).
Imperativo Você diz como fazer passo a passo (ex: Bash scripts, Ansible em partes).
Imutabilidade Se um servidor apresenta problema, você não entra nele para arrumar. Você destrói e o IaC sobe um novo idêntico do zero (Cattle vs. Pets).
GitOps O Git se torna a "Única Fonte da Verdade" (Single Source of Truth). O estado da infra reflete exatamente o que está na branch main.

👁️ Observabilidade (Os 3 Pilares)

Capacidade de inferir o estado interno de um sistema a partir das suas saídas externas.

  • 📊 Métricas (Metrics): Dados numéricos ao longo de um período de tempo. Útil para alertas e painéis. Ex: CPU em 90%, 500 req/segundo. (Ferramentas: Prometheus, Grafana).
  • 📝 Logs: Registros imutáveis, com timestamp, sobre eventos que aconteceram no sistema. Servem para investigação e auditoria. Ex: "Usuário X falhou login às 10:00". (Ferramentas: ELK Stack, Loki).
  • 🔗 Traces (Rastreamento Distribuído): Acompanha a jornada de uma requisição única passando por múltiplos microsserviços. Crucial para achar gargalos em sistemas distribuídos. (Ferramentas: Jaeger, OpenTelemetry).

🛡️ DevSecOps & Shift-Left

"Shift-Left" significa mover a preocupação com a Segurança e Testes para o início (esquerda) do ciclo de desenvolvimento, e não deixar para o final.

SAST Static Application Security Testing: Escaneia o código-fonte parado (sem rodar) atrás de vulnerabilidades e más práticas (ex: SonarQube).
SCA Software Composition Analysis: Verifica as bibliotecas/dependências de terceiros no projeto em busca de falhas conhecidas (CVEs).
DAST Dynamic Application Security Testing: Tenta hackear/atacar a aplicação enquanto ela está rodando para achar falhas como SQL Injection.
Secret Scanning Impede (ou alerta) que desenvolvedores "commitem" senhas, chaves AWS e tokens direto no código-fonte.

📈 Métricas DORA (Desempenho)

Padrão ouro do Google DevOps Research and Assessment para medir a performance de times de engenharia.

  • Frequência de Deploy: Com que frequência a equipe libera código para produção? (Medida de velocidade).
  • Lead Time para Mudanças: Quanto tempo leva para um commit chegar a produção? (Velocidade).
  • Tempo de Restauração (MTTR): Quando há um incidente, quão rápido o time consegue restaurar o serviço? (Estabilidade).
  • Taxa de Falha de Mudança (CFR): Qual a porcentagem de deploys que causam falhas exigindo rollback/hotfix? (Estabilidade).

🚀 Estratégias de Implantação Avançadas

Formas seguras de enviar novas versões ao cliente sem derrubar o sistema (Zero Downtime).

Blue/Green Mantém dois ambientes de produção idênticos. O "Blue" é o atual. Você atualiza o "Green". Se tudo estiver bem, você vira o roteamento/tráfego de rede para o Green instantaneamente.
Canary Release (Deploy Canário): Libera a nova versão para uma pequena porcentagem dos usuários (ex: 5%). Monitora-se o comportamento. Se der certo, aumenta gradativamente até 100%.
Feature Toggles (Flags): O código novo já está em produção, mas escondido atrás de uma variável `if (nova_feature_ativa)`. Permite ligar/desligar funcionalidades via painel sem novo deploy.
