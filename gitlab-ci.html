🦊 GitLab CI Cheat Sheet

Guia rápido de pipelines, stages, rules e sintaxe do .gitlab-ci.yml

📁 Estrutura Básica (.gitlab-ci.yml)

O arquivo deve ficar na raiz do repositório. Ele define imagens, estágios e os jobs (tarefas).

# Define a imagem Docker padrão para todos os jobs
image: node:18-alpine

# Define a ordem de execução dos estágios
stages:
  - build
  - test
  - deploy

# Declaração de um Job
compilar_projeto:
  stage: build # Associa o job a um estágio
  script:
    - echo "Iniciando o build..."
    - npm install
    - npm run build

🏗️ Estágios (Stages) e Ordem

Controlam o fluxo do pipeline. Os estágios rodam sequencialmente. Jobs no mesmo estágio rodam em paralelo.

  • Se um job falhar em um estágio, o pipeline inteiro para (por padrão), e o próximo estágio não é executado.
  • Jobs que não declaram um stage: assumem o estágio padrão test.
  • Estágios padrão implícitos: .pre, build, test, deploy, .post.

📦 Cache vs Artifacts (Artefatos)

Dois conceitos cruciais para otimização e passagem de arquivos.

Recurso Uso Principal
cache: Guarda dependências (ex: node_modules) para acelerar execuções futuras. Não garante que estará lá no próximo job.
artifacts: Arquivos gerados pelo build (ex: executáveis, relatórios). São passados adiante para os próximos estágios garantidamente. 
build_job:
  stage: build
  script: npm run build
  artifacts:
    paths:
      - dist/ # Passa a pasta dist para o deploy
    expire_in: 1 week # Expira após 1 semana
  cache:
    key: $CI_COMMIT_REF_SLUG # Cache por branch
    paths:
      - node_modules/

🐳 Imagens e Serviços (Services)

Subir containers auxiliares durante o job (como banco de dados para testes).

testar_com_banco:
  stage: test
  image: python:3.9
  services: # Sobe serviços atrelados ao job
    - name: postgres:13
      alias: db # Nome do host no teste
  variables: # Variáveis para configurar o serviço
    POSTGRES_DB: banco_teste
    POSTGRES_PASSWORD: senha123
  script:
    - pip install pytest psycopg2
    - pytest

🎯 Rules (Controle de Execução)

Mecanismo moderno para decidir quando um job deve (ou não) rodar. Substitui o antigo only/except.

deploy_producao:
  stage: deploy
  script: ./deploy.sh
  rules:
    # 1. Roda automaticamente se for branch main
    - if: '$CI_COMMIT_BRANCH == "main"'
      
    # 2. Permite rodar MANUALMENTE se for tag v*
    - if: '$CI_COMMIT_TAG =~ /^v\d+/'
      when: manual
      
    # 3. Nunca roda em Merge Requests
    - if: '$CI_PIPELINE_SOURCE == "merge_request_event"'
      when: never

🌐 Variáveis Predefinidas (CI Variables)

O GitLab injeta dezenas de variáveis úteis em tempo de execução.

$CI_COMMIT_BRANCH Nome da branch do commit (ex: main, feature-x).
$CI_COMMIT_SHA O hash completo de 40 caracteres do commit.
$CI_PIPELINE_ID ID numérico único para a execução do pipeline atual.
$CI_PROJECT_NAME Nome do projeto/repositório.
$CI_REGISTRY_IMAGE Endereço base para o Container Registry deste projeto.

Dica de Segurança: Crie variáveis sensíveis (Senhas, Tokens da AWS) em Settings > CI/CD > Variables na interface do GitLab (Marque como Masked).

🔗 Reutilização (Include e Extends)

Evite repetição de código (DRY) quebrando seus YAMLs ou herdando configurações.

# Importar outro arquivo YAML para este pipeline
include:
  - local: '/templates/.ci-deploy.yml'

# Template "Escondido" (começa com ponto)
.template_job:
  image: alpine:latest
  before_script:
    - apk add curl

# Herdar do template
meu_job_real:
  extends: .template_job
  script:
    - curl http://exemplo.com

🌍 Ambientes (Environments)

Usado para rastrear deploys. Habilita botões de "Rollback" e links diretos na interface gráfica do GitLab.

deploy_staging:
  stage: deploy
  script: echo "Deploy feito!"
  environment:
    name: staging
    url: https://staging.meuapp.com.br
    # Evento executado se o ambiente for "parado"
    on_stop: stop_staging 

stop_staging:
  stage: deploy
  script: echo "Desligando servidor..."
  when: manual
  environment:
    name: staging
    action: stop
